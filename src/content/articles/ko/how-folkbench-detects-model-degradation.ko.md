Folkbench는 [무결성 모니터(Integrity Monitor)](https://folkbench.com/ko/arena)에 **모델 성능 저하 탐지** 기능을 정식 출시했습니다. 기존 모델 순위는 공식 환경에서의 이론적 역량 상한을 평가하고, 일반 API 중계 디렉터리는 공시 가격과 HTTP 가용성·응답 지연 시간만 보여줍니다. 어느 쪽도 실제 운영 환경의 핵심 질문, 즉 서드파티 API 중계 경로를 거칠 때도 추론 깊이·제약 준수·모델 고유 특성이 공식 직연결 API와 일치하는지에는 답하지 못합니다.

이 공백을 메우기 위해 Folkbench는 **시사 이슈**와 **모델 지문(Model Fingerprint)** 두 차원의 자동화 프로브 체계를 구축하고, 동일한 측정 주기마다 **독립적인 공식 직연결 API 키**로 실시간 보정을 수행합니다. 중계 경로의 실측치를 실시간 공식 기준선에 직접 고정함으로써 은밀한 품질 이탈을 조기에 포착하고 주관적 의심을 검증 가능한 공개 지표로 전환합니다.

이번 기능의 핵심 설계는 다음과 같습니다.

- **이중 차원 프로브**: 시간에 따라 갱신되는 시사 프로브와 추론 습관·토큰 배분·API 지문을 추적하는 모델 지문 프로브를 결합해 정적 캐싱과 표면적 모방을 동시에 차단합니다.
- **독립 공식 직연결 보정**: 외부 중계를 거치지 않는 독립 공식 API 키로 동일 프로브를 동시 실행해 모델 제조사 업데이트와 개별 중계기 이상을 분리합니다.
- **모델 × 서비스 그룹 단위 측정**: 사이트 전체를 뭉뚱그린 평균 대신 모델과 세부 서비스 그룹별로 프로브 일치율, 입력 토큰, 사고 토큰, 모델 지문, 가용 캐시 점검 결과를 산출합니다.
- **검증부터 전환까지의 일관된 흐름**: 무결성 모니터를 4대 공개 순위, 중계 서비스 나란히 비교, 오픈소스 데스크톱 클라이언트 Folkbench Switch와 연결합니다.

## 기존 순위와 연결 모니터링이 성능 저하를 놓치는 이유

중계 아키텍처에서는 호출자와 모델 제조사 사이에 게이트웨이가 놓입니다. 비용 절감 압박이나 피크 시간대 트래픽 분산 과정에서 네트워크 지표로는 드러나지 않는 세 가지 품질 저하가 발생할 수 있습니다.

- **은밀한 모델 교체**: 플래그십 모델을 호출했으나 혼잡 시간대나 긴 컨텍스트에서 저가형 경량 모델이나 구형 스냅샷으로 우회됩니다.
- **추론 예산 축소**: 모델 이름은 유지되지만 reasoning effort가 낮춰지거나 내부 사고 단계가 조기 절단되어 성급한 답변이 출력됩니다.
- **문맥·출력 절단**: 토큰 절감을 위해 이전 대화 이력이 잘리거나 최대 출력 길이가 제한되어 다단계 과제에서 조건 누락이 발생합니다.

![그림 1 와이어프레임 도해: 일반 모니터링이 HTTP 200과 빠른 응답을 정상으로 표시하는 동안 게이트웨이 아래에서 은밀한 모델 교체, 추론 예산 축소, 문맥 절단이 발생하는 구조.](/blog/figures/how-folkbench-detects-model-degradation/degradation-layers-ko.svg)

*그림 1: 표면적인 네트워크 정상 상태(`HTTP 200`, 빠른 첫 토큰 응답, 매끄러운 단문 답변)는 모델 역량의 온전한 전달을 보장하지 않습니다. 중계 계층의 우회 라우팅, 추론 삭감, 문맥 절단은 일반 접속 점검으로 드러나지 않습니다.*

세 경우 모두 **표면적 연결성은 정상으로 보입니다**: HTTP `200`이 반환되고 간단한 대화는 매끄러우며 추론이 짧아져 오히려 응답 속도가 빨라 보이기도 합니다. 반대로 생성 모델의 자연스러운 무작위성 때문에 정상 경로에서도 간헐적 실패가 나타나므로, [모델이 정말 ‘너프’됐을까?](/ko/blog/did-the-model-get-dumber/)에서 짚었듯 단편적인 스크린샷만으로는 정상 변동과 구조적 저하를 구분할 수 없습니다.

## 일반 수동 점검이 현대 라우팅을 뚫지 못하는 이유

성능 저하가 의심될 때 사용자가 자주 시도하는 두 가지 수동 점검은 현대 게이트웨이 라우팅 앞에서 쉽게 무력화됩니다.

1. **“너 무슨 모델이야?”라고 직접 묻기**: 언어 모델은 앞단 프록시 구조를 인지하지 못합니다. 시스템 프롬프트 지정이나 학습된 문구만으로 대체 모델도 목표 모델명을 그대로 답합니다.
2. **고정된 유명 문제 재사용**: 널리 알려진 퍼즐은 이미 소형 모델의 학습 코퍼스에 포함되어 있으며, 동일한 테스트 문항을 반복하면 **정적 캐시** 반환이나 테스트 프롬프트만 정상 경로로 우회시키는 편법이 가능해집니다.

![그림 2 와이어프레임 도해: 모델 이름을 직접 묻는 테스트와 고정된 유명 문제가 게이트웨이 프롬프트 주입 및 캐시·화이트리스트 필터에 막히는 이유.](/blog/figures/how-folkbench-detects-model-degradation/naive-checks-trap-ko.svg)

*그림 2: 흔한 수동 자가 점검이 실패하는 두 가지 구조. 왼쪽처럼 게이트웨이 시스템 프롬프트만 주입해도 실제 가중치와 무관하게 원하는 모델명을 말하며, 오른쪽처럼 반복되는 고정 테스트는 게이트웨이 필터가 식별해 정적 캐시나 정상 경로로만 우회시킬 수 있습니다.*

## 이중 차원 프로브: 현재 이해력과 모델 지문의 동시 검증

은밀한 품질 저하를 정확히 가려내기 위해 Folkbench는 매 측정 창마다 두 가지 상호 보완적 프로브 차원을 동시에 실행합니다.

![그림 3 이중 차원 프로브 아키텍처: 시사 프로브와 모델 지문 프로브를 동일 시간 창에서 독립 공식 직연결 API 키와 중계 서비스 모델×그룹 경로로 병렬 전송하는 구조.](/blog/figures/how-folkbench-detects-model-degradation/probe-architecture-ko.svg)

*그림 3: 동일 창 병렬 보정 아키텍처. 시사 프로브는 정적 캐시와 구형 스냅샷 우회를 차단하고, 모델 지문 프로브는 프로브 일치율·입력 토큰·사고 토큰·모델 지문·캐시 점검을 수집해 독립 공식 직연결 기준선과 나란히 대조합니다.*

### 1. 시사 차원 프로브: 정적 캐시와 구형 스냅샷 차단

시사 프로브는 최근 실제 사건의 시간 순서와 최신 맥락 조건을 다단계 추론 과제에 반영합니다. 문제 문맥이 현실 시간에 맞춰 계속 갱신되므로 사전 계산된 정적 캐시가 통하지 않으며, 최신 사건의 선후 관계와 새 제약 조건을 결합해야 하는 과제에서는 지식 기준일이 지난 대체 스냅샷이나 과도하게 압축된 모델이 정합성 오류를 드러내기 쉽습니다.

### 2. 모델 지문 차원 프로브: 정답 여부와 함께 ‘사고 습관·토큰 지표’ 확인

비교적 준수한 대체 모델로 바뀌거나 동일 모델의 사고 예산만 절반으로 깎인 경우 단순 객관식 정오답만으로는 구별이 어렵습니다. 모델 지문 프로브는 다단계 제약 준수와 형식 경계에서 드러나는 모델별 행동 패턴과 함께 엔드포인트가 반환하는 핵심 텔레메트리—**프로브 일치율**, **입력 토큰과 사고 토큰(Reasoning Tokens)**, **모델 지문 및 가용 캐시 점검**—을 병행 수집합니다. 추론 강도가 몰래 낮아지면 문장은 자연스러워 보여도 **사고 토큰량과 프로브 일치율이 함께 하락**하는 특징이 나타납니다.

## 독립 공식 직연결 API 키 보정: 절대 점수를 실시간 기준선으로 전환

프로브 점수가 특정 시점에 하락하더라도 중계기 단독 측정만으로는 원인을 단정할 수 없습니다. 공식 모델 자체의 업데이트나 일시적 변동, 혹은 신규 문항의 공식 기본 통과율 영향일 수도 있기 때문입니다. 이를 해결하기 위해 **Folkbench는 모든 성능 저하 프로브를 독립적인 공식 직연결 API 키로 동일 시간 창에서 병행 실행해 실시간 공식 기준선을 확립**합니다.

![보정 메커니즘 와이어프레임 도해: 원인 판별이 모호한 단독 관측(왼쪽)과 공식 직연결 레일·중계 레일을 동일 평가 창 W_t의 동기 대조 게이트로 함께 통과시키는 이중 레일 보정(오른쪽) 비교.](/blog/figures/how-folkbench-detects-model-degradation/baseline-calibration-ko.svg)

*보정 메커니즘: 동시점 공식 기준이 없는 단독 관측(왼쪽)은 상류 변동과 중계기 삭감을 구분할 수 없습니다. 이중 레일 동시 보정(오른쪽)은 독립 공식 직연결 키와 대상 `모델 × 그룹`을 같은 `W_t` 창에서 병행 실행해 상대 편차를 추출합니다.*

| 관측 상황 | 보정 없는 단독 측정 | 독립 공식 직연결 키 실시간 보정 |
| --- | --- | --- |
| 공식 모델 자체의 미세 조정·변동 | 전체 변동을 중계기 탓으로 오인할 위험 | 공식 기준선도 함께 이동해 상류 변동과 개별 중계 이상을 분리 |
| 공식 기준선 안정, 특정 중계기 하락 | 동시점 비교 기준이 없어 편차 검증 곤란 | 일치율과 사고 토큰이 공식 기준선과 뚜렷이 괴리됨을 확인 |
| 동일 중계기 내 그룹별 편차 | 안정 그룹 수치로 저가 그룹 축소를 가림 | `모델 × 서비스 그룹` 단위로 기준선과 개별 대조 |

![그림 4 메커니즘 예시도(실측치 아님): T3 이후 공식 기준선과 중계기가 함께 움직이는 상류 변동 사례(Case A)와 공식 기준선은 유지되는데 중계기 일치율·사고 토큰만 급락하는 사례(Case B) 비교.](/blog/figures/how-folkbench-detects-model-degradation/calibration-signals-ko.svg)

*그림 4(원리 설명용 예시도이며 실측 수치가 아닙니다): 독립 공식 기준선을 통한 원인 분리. Case A처럼 `T3` 이후 두 선이 같이 이동하면 공식 모델 또는 문항군 변동이고, Case B처럼 공식 선이 일정한 가운데 일치율과 사고 토큰이 동반 하락할 때 해당 `모델 × 그룹` 경로의 이탈을 짚어냅니다.*

동시에 [무결성 모니터](/ko/arena)에서 명시하듯 **단 한 번의 응답이나 고립된 백분율 하나로 모델 교체를 최종 단정할 수는 없습니다**. 표본 크기, 연속 시간 창, 토큰 분포, 점검 조건을 함께 해석해야 객관적이고 재검증 가능한 조기 경보 신호가 됩니다.

## Folkbench가 기존 모델·중계 평가 사이트와 다른 점

기존 평가 사이트는 고정 데이터셋 기준 이론 상한을 매기거나 가격과 HTTP 연결만 보여줍니다. Folkbench는 다음 네 계층을 연결해 실제 전달 품질 검증까지 닫아줍니다.

![그림 5 Folkbench 전체 흐름도: 4대 공개 순위(/rankings*), 무결성 모니터(/arena), 나란히 비교(/stations/compare), Folkbench Switch를 연결한 검증-전환 체계.](/blog/figures/how-folkbench-detects-model-degradation/folkbench-stack-ko.svg)

*그림 5: 정적 모델 순위표와 단순 Ping 점검을 넘어서는 4단계 실무 흐름. 그룹별 선별(`/rankings*`), 성능 저하 감사(`/arena`), 동일 그룹 정밀 비교(`/stations/compare`), 로컬 안전 전환(`Folkbench Switch`)을 하나로 이으며, 무결성 및 캐시 추적은 웹 평가 플랫폼에서 상시 운영됩니다.*

1. **모델 및 서비스 그룹 단위 실측**: 한 업체 안의 특가 그룹과 공식 키 안정 그룹을 섞지 않고 실제 구매 단위별로 분리 평가합니다.
2. **4대 전문 공개 순위**: **[가용률](/ko/rankings)**(가짜 `200` 오류와 스트림 중단을 걸러냄), **[안정성](/ko/rankings/stability)**(장시간·피크 타임 지속성), **[응답 속도](/ko/rankings/latency)**(TTFT와 지속 생성 속도 분리), **[세션 비용](/ko/rankings/cost)**(실제 코딩 세션 기준 지출).
3. **무료 [무결성 모니터](/ko/arena) 및 [중계 서비스 비교](/ko/stations/compare)**: 개인이 별도 공식 키와 동적 문제 세트를 유지하지 않고도 보정된 지표와 동화면 비교를 바로 활용할 수 있습니다.
4. **오픈소스 클라이언트 [Folkbench Switch](https://github.com/Folkbench/folkbench/releases)**: Tauri + Rust 기반(macOS `.dmg` / Windows `.exe`)으로 Claude Code, Codex, Gemini CLI, Aider, OpenCode, Kimi CLI 설정을 관리하며 **diff 미리보기**, **Codex 공식 OAuth 자격 증명 보호**, 공개 경로 탐색 및 로컬 사용량 추정을 지원합니다. *(무결성 및 캐시 모니터링은 웹 평가 플랫폼 기능입니다.)*

## 실전 활용 4단계

1. [가용률](/ko/rankings), [안정성](/ko/rankings/stability), [응답 속도](/ko/rankings/latency), [세션 비용](/ko/rankings/cost)에서 작업 요구에 맞는 모델·그룹 후보를 먼저 추립니다.
2. [무결성 모니터](/ko/arena)에서 연속 시간 창의 프로브 일치율, 사고 토큰, 모델 지문이 공식 기준선과 일치하는지 점검합니다.
3. 결제 전 [중계 서비스 비교](/ko/stations/compare)에서 내가 사용할 정확한 그룹 지표를 대조합니다.
4. [Folkbench Switch](https://github.com/Folkbench/folkbench/releases)에 주 경로와 예비 경로를 저장해 두어 지표 이탈 시 diff를 확인하고 몇 초 만에 전환합니다.

오늘날 API 인프라는 서류상 모델 성능뿐 아니라 실제 경로가 약속된 역량을 그대로 전달하는지까지 검증해야 합니다. Folkbench는 시사 프로브, 모델 지문, 독립 공식 직연결 보정을 상시 공개 체계로 통합해 투명하고 재검토 가능한 선택 기준을 제시합니다.
