> 以下の仕様、公式価格、スコアは、Anthropic またはその引用元の公開ページから転記したもので、確認日は 2026 年 10 月 2 日です。Folkbench はこれらのベンチマークを再実行していません。「約 40% 安い」「約 5 分の 1 のコスト」といった開発元の記述は、同社独自のテスト環境についてのものです。

Claude Opus 5.5 は 2026 年 9 月 22 日に発表された、Claude 5.5 ファミリーの最初のモデルです。Claude API のモデル ID は `claude-opus-5-5` です。モデルページには、コンテキストウィンドウ 100 万トークン、最大出力 128K トークン、常時有効の適応型思考（adaptive thinking）、デフォルトの effort は `medium`、公式価格は 100 万入力トークンあたり $4、100 万出力トークンあたり $20 と記載されています。公開ページには、パラメーター数も学習計算量も示されていません。

同じ日に確認できる位置づけは、主に 3 点です。公式価格は Opus 5 より安く、Fable 5.1 の $10 / $50 よりはるかに安価です。発表ページに掲載されたコーディングと知識労働の行では、Opus 5.5 が Fable 5.1 と Opus 5 を上回り、そのうち大半の行で GPT-6 Astra も上回っています。逆の結果になった行が 2 つあり、Terminal-Bench-Science 0.1 と Zapier の AutomationBench では Astra の点推定が上回っています。範囲が明確な日常的タスクについては [Claude Sonnet 5.5](../claude-sonnet-5-5-review-pricing/) と比べてください。OpenAI 側の長コンテキスト向け料金区分は [GPT-6.1 Sol](../gpt-6-1-sol-review-pricing/) にまとめています。

「信頼できる知識カットオフ」とは、モデルが元から持っている知識が最も充実しているとされる時点のことです。コンテキストウィンドウとは別のもので、リクエストに添付したファイルは、そのリクエストのコンテキスト内に引き続き含まれます。

Fast mode は、同じモデル ID で使える速度の切り替えです。更新情報ページでは、Claude API でのみ利用できるリサーチプレビューとされています。リクエストでは `speed: "fast"` を指定し、beta ヘッダー `fast-mode-2026-02-01` を付けます。発表ページに示された価格は 100 万トークンあたり $8 / $40、出力速度は最大で約 2.5 倍で、Claude Code と Claude Platform で利用できると書かれています。更新情報ページによると、Amazon Bedrock、Claude Platform on AWS、Google Cloud、Microsoft Foundry ではこの fast mode は提供されていません。

思考予算を手動で指定すると拒否されます。思考の深さは effort だけで制御します。

## 公式価格

単位は 100 万トークンあたりの米ドルです。Opus 5.5 の 5 分キャッシュ書き込み、1 時間キャッシュ書き込み、バッチ価格は更新情報ページによるものです。Opus 5 のキャッシュ書き込みは、発表ページの比較表にある単一の「cache writes」の数値で、この表は 5 分と 1 時間を分けていません。Fable 5.1、Sonnet 5.5、Haiku 4.5 の入力・出力価格は、モデルページの比較行から取りました。Sonnet 5 は引き続き legacy と表示されており、モデルページ上の入力・出力価格は Sonnet 5.5 と同じです。ダッシュは、本記事がその欄を一次情報の価格行から取っていないことを示します。

| 100 万トークンあたり | Opus 5.5 | Opus 5 | Fable 5.1 | Sonnet 5.5 | Haiku 4.5 |
| --- | --- | --- | --- | --- | --- |
| 入力 | $4 | $5 | $10 | $2 | $1 |
| 出力 | $20 | $25 | $50 | $10 | $5 |
| キャッシュ読み取り | $0.20 | $0.50 | — | $0.20 | — |
| キャッシュ書き込み | 5 分 $5、1 時間 $8 | $6.25 | — | 5 分 $2.50、1 時間 $4 | — |
| バッチ入力 / 出力 | $2 / $10 | — | — | 公式価格の 50% | — |
| Fast mode 入力 / 出力 | $8 / $40 | — | — | — | — |

Opus 5 と比べると、新規入力と出力の公式価格は 20% 下がり、$5 / $25 から $4 / $20 になりました。発表ページはキャッシュ読み取りが $0.50 から $0.20 に下がったとし、これがエージェントやコーディングの請求額の大半を占めると述べています。Anthropic はワークロードについての主張も別に示しています。デフォルト設定では、モデルが消費するトークンも少なくなるため、典型的なタスクの費用は Opus 5 より約 40% 低くなるというものです。この 40% は、同社独自のテスト環境についての数字です。実際の請求額は、effort、キャッシュヒット、ツールのラウンド数、そしてバッチや fast mode を使うかどうかに左右されます。

バッチ処理は新しい公式価格の半額です。Fast mode は新しい公式価格の 2 倍で、更新情報ページでは Claude API に限定されています。

公式価格から手計算できる例を 3 つ挙げます。いずれも、該当する種類の入力トークン 10 万と出力トークン 5,000 の組み合わせです。キャッシュの行は、usage の記録が実際にこれらのトークンを読み取りとして計上していることを前提としています。

| リクエスト | 計算 | 金額 |
| --- | --- | --- |
| 未キャッシュ入力 10 万、出力 5,000 | 0.1 × $4 + 0.005 × $20 | $0.50 |
| キャッシュ読み取り 10 万、出力 5,000 | 0.1 × $0.20 + 0.005 × $20 | $0.12 |
| 5 分キャッシュ書き込み 10 万、出力 5,000 | 0.1 × $5 + 0.005 × $20 | $0.60 |

1 時間キャッシュ書き込みの場合は、上の $5 ではなく $8 を使います。中継サービスやクラウドマーケットプレイスでの実際の取引価格は、この表には含まれていません。

## Opus 5、Fable 5.1 と比べてリクエストの何が変わったか

| 動作 | Opus 5.5 | Opus 5 | Fable 5.1 |
| --- | --- | --- | --- |
| API ID | `claude-opus-5-5` | `claude-opus-5` | `claude-fable-5-1` |
| コンテキスト / 最大出力 | 1M / 128K | 1M / 128K | 1M / 128K |
| 思考 | 常時有効。`disabled` と手動予算は 400 を返す | デフォルトで有効。effort が `high` 以下なら `disabled` を受け付ける | モデルページでは常時有効と記載 |
| effort 省略時のデフォルト | `medium` | `high` | `high` |
| 信頼できる知識カットオフ | 2026 年 6 月 | 本記事では別途引用していない | 2026 年 6 月 |
| 公式価格（入力 / 出力） | $4 / $20 | $5 / $25 | $10 / $50 |
| キャッシュ読み取り | $0.20 | $0.50 | — |

更新情報ページには、「Opus 5 で動いていたコード」を失敗させる 4 つの変更がまとめて記載されています。最初の 3 つは Fable 5.1 にも当てはまります。モデル文字列を差し替えるだけでは、これらに引っかかります。

```text
model: claude-opus-5-5
thinking: {"type": "adaptive"}
tool_choice: {"type": "auto"}
output_config.effort: medium
# 400：thinking のタイプが disabled、または enabled で budget_tokens を指定
# 400：tool_choice が any、または tool
# 400（Claude API と Google Cloud のみ）：ツールタイプ computer_20251124
```

`thinking` を省略することと `adaptive` を送ることは同等です。`tool_choice` の `auto` と `none` は引き続き有効で、トークン計数のエンドポイントでも同様です。スキーマに準拠した JSON が必要な場合、更新情報ページは strict なツール呼び出しか構造化出力を使い、どのような場合にツールを呼び出すかをプロンプトに明記するよう案内しています。

Claude API と Google Cloud では、`computer_20251124` を `computer_toolset_20260801` に置き換え、旧来のコンピューター操作（computer use）用 beta ヘッダーを外します。更新情報ページによると、Amazon Bedrock 上の Opus 5.5 は引き続き `computer_20251124` を受け付けます。すでに新しいツールセットを使っているブラウザ操作の統合では、この点についてコードを変更する必要はありません。

4 つ目の 400 は、思考ブロックのバインディングに関するものです。2026 年 8 月 31 日 00:00 UTC 以降に作成されたアカウントでは、Claude API とクラウドプラットフォーム上で、Opus 5.5 の思考ブロックが生成された後にシステムプロンプト、ツール一覧、またはそれ以前のメッセージが変更されていると、そのブロックを再送したときに 400 が返されます。ドキュメントが示す方法は、追記のみの履歴です。指示を変える必要がある場合は、会話の途中でシステムメッセージを使います。それより前に作成されたアカウントでは、同じチェックを明示的に有効にした場合にのみ適用されます。

リクエスト自体は成功しても、動作が変わる点も 3 つあります。effort を省略すると現在は `medium` で動作しますが、Opus 5 では同じ省略で `high` になっていました。同じ effort でも、Opus 5.5 は Opus 5 よりターンごとに多く思考する傾向があり、`xhigh` と `max` では特に顕著です。古い設定からコピーしてきた effort の値は新たなコストポイントになり、`max_tokens` には思考ブロックのための余裕を残しておく必要があります。

ツール呼び出しの合間に書かれるテキストは、思考ブロックの中に戻されます。デフォルトの display が `omitted` の場合、これらのブロックのテキストは空になります。以前はこのテキストを進捗としてストリーミング表示していた UI は静かになりますが、リクエスト自体は成功します。こうした進捗行が必要な場合は、display を別途設定し、位置で推測するのではなく、ブロックの `type` で取り出してください。

生物学分類器が、サイバーセキュリティ分類器と並行して動作します。推論を可視の回答に書き写すようモデルを仕向けるプロンプトは、`reasoning_extraction` として拒否される可能性があります。更新情報ページによれば、図表やスクリーンショットは視覚ツールを追加する前の段階でもより正確に読み取れるようになっているため、画像読み取りの弱さを補うために書いたプロンプトは、個別に再実行して確かめる価値があります。

拒否されたリクエストは HTTP 200 で返り、`stop_reason` は `"refusal"` になります。これは通信の失敗ではありません。課金されるかどうかは拒否のカテゴリによって異なり、レート制限には引き続きカウントされます。

## 発表ページのベンチマークをどう読むか

次の表は、2026 年 10 月 2 日時点で発表ページに掲載されていたものです。脚注に別の記載がない限り、Opus 5.5 は適応型思考で、effort は max です。Terminal-Bench 4.0 がその脚注の対象で、Opus 5.5 は `xhigh`、GPT-6 Astra は `high` を使い、それぞれのモデルについて公表された最高スコアを採っています。Astra と GPT-5.6 Sol の数値は OpenAI の報告からの引用です。本番環境のセーフガードは有効でした。セーフガードが介入した場合、サイバーセキュリティのタスクは Opus 4.8 が、生物学およびフロンティア LLM 開発のタスクは Opus 5 が完了させています。Anthropic は、これによって Opus 5.5 のスコアが押し下げられるとしています。

| ベンチマーク | Opus 5.5 | Fable 5.1 | Opus 5 | GPT-6 Astra | GPT-5.6 Sol |
| --- | --- | --- | --- | --- | --- |
| Terminal-Bench 4.0 | 66.4% | 55.8% | 52.3% | 57.9% | 37.3% |
| FrontierCode v1.1 (Main) | 54.4% | 50.3% | 48.0% | 53.3% | 47.5% |
| CursorBench 4.0 | 57.8% | 51.8% | 46.6% | — | 41.7% |
| GDPval-AA v2.1 | 1846 | 1735 | 1708 | 1542 | 1588 |
| AutomationBench | 40.0% | 31.4% | 26.9% | 41.4% | 28.8% |
| Humanity's Last Exam、ツールあり | 67.7% | 65.6% | 63.6% | 57.2% | — |
| Terminal-Bench-Science 0.1 | 58.7% | 52.6% | 29.0% | 64.6% | 22.4% |
| OSWorld 2.1、partial | 81.8% | 80.7% | 74.0% | — | — |
| Chartography、ツールあり | 89.0% | 88.4% | 83.4% | — | — |

差は、公表された誤差と並べて読んでください。Terminal-Bench 4.0 では、Opus 5.5 の誤差が ±2.6 ポイント、他の Claude モデルは ±1.6～±2 ポイントです。66.4% から Astra の 57.9%、Fable の 55.8% までの差は、いずれもこれらの誤差より大きくなっています。同じ脚注には、公開ランキング上の Opus 5 は 51.8% で、同社の環境での再現値は 52.3% であり、ノイズの範囲内だとも書かれています。

Terminal-Bench-Science の誤差は、モデルごとに ±3.5～±5 ポイントです。Astra の 64.6% と Opus 5.5 の 58.7% の差はこの誤差の幅に近い大きさで、点推定では Astra が上回っています。公開ランキング上の Opus 5 は 30.0% で、同社の環境での再現値は 29.0% です。

AutomationBench は Zapier が実施しています。この実行にはフォールバックモデルがなかったため、セーフガードの介入は失敗として数えられました。Anthropic は、実際のスコアはもっと高くなるとしています。掲載された 40.0% と Astra の 41.4% はきわめて接近した公表結果で、点推定では Astra が上回っています。GDPval-AA v2.1 は 44 職種の実際の専門業務を対象にした Elo で、Opus 5.5 が 1846、Fable 5.1 が 1735、Opus 5 が 1708、Sol が 1588、Astra が 1542 です。

同じ発表ページのコストのグラフには、デフォルトの effort `medium` で取った 2 つ目のスコアの組も載っています。FrontierCode 54.6%、CursorBench 52.5% です。比較表に掲載されているのは 54.4% と 57.8% です。これらは、2 つの effort 設定での 2 つの数値として扱ってください。グラフの注記には、medium effort の FrontierCode は約 5 分の 1 のタスクあたりコストで Astra の最高スコア 53.3% を上回り、Terminal-Bench は約 40% のコストで Astra に並ぶとも書かれています。これらは、Anthropic 独自のテスト環境におけるタスクあたりコストの主張です。

むしろ覚えておきたいのは、表の下にある一文です。Anthropic 自身の利用では、Opus 5.5 と Fable 5.1 の差はスコアが示すよりも小さく、この水準でのベンチマークの差は実際のタスクの指針としては弱くなる、というものです。発表ページに並ぶ顧客の声は、選ばれた証言です。何を再実行すべきかのヒントにはなりますが、この表の一部ではありません。

## トラフィックを切り替える前に確認すること

1. `claude-opus-5-5` を固定します。完了した結果のモデル名も確認してください。セーフガードが介入すると、サイバーセキュリティのタスクは Opus 4.8 が、生物学やフロンティア LLM 開発のタスクは Opus 5 が完了させることがあります。それでもログ上のリクエストモデルは `claude-opus-5-5` のままの場合があります。
2. 機密情報を含まない同じセットを、`low`、`medium`、`high`、`xhigh`、`max` のそれぞれで再実行します。成功率、実時間（ウォールクロック）、入力、キャッシュ読み取り、キャッシュ書き込み、出力、費用を記録してください。
3. `thinking: {"type": "disabled"}` や、`budget_tokens` を伴う手動予算は送らないでください。effort は明示的に設定します。省略した場合は、Opus 5 の `high` ではなく `medium` になります。
4. `tool_choice` は `auto` か `none` だけを使います。Claude API と Google Cloud でのコンピューター操作は、`computer_toolset_20260801` に移行します。
5. 思考ブロックを再送する会話は、追記のみに保ちます。2026 年 8 月 31 日以降に作成されたアカウントでは、Opus 5.5 の思考ブロックより前のプレフィックスを変更すると 400 が返されます。
6. HTTP 200 の拒否応答と通信の失敗は、分けて数えます。
7. 短いプロンプト 1 つと、キャッシュにヒットするはずのプロンプト 1 つで、請求額を確認します。5 分書き込み、1 時間書き込み、バッチ、fast mode は、4 つの異なる料金体系です。
8. 範囲が明確で、この Opus のループを必要としないタスクには、引き続き [Sonnet 5.5](../claude-sonnet-5-5-review-pricing/) の $2 / $10 を検討してください。科学系のエージェントタスクと Zapier の業務ワークフローでは、発表ページに掲載された点推定で Astra が上回っています。

モデルを選んだ後、各中継サービスがこの ID を提供しているかどうか、またその時点の稼働率と価格は、ディレクトリに公開済みの記録を基準にしてください。本記事は中継サービス同士を比較するものではなく、開発元の公式価格を特定の中継サービスでの実際の請求価格として扱うこともしません。
